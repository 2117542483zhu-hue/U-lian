# 动作自检使用说明

这个文件夹里是一套可以跑起来的动作自检程序：给一段深蹲视频，它会输出骨架叠加的画面、动作问题判定和纠正建议。

原理是"两步走"：先用姿态识别算出关节角度等数字（这一步是确定性计算），再让大模型把这些数字翻译成学生能听懂的教练语言（这一步是生成式）。答辩时这是最重要的技术说明，因为数字不能靠模型猜。

---

## 一、第一次使用（只做一次）

1. 确认电脑装了 Python 3.11 或 3.12。如果没装，去 https://www.python.org/downloads/ 下载，安装时务必勾选 **Add Python to PATH**。
2. 在这个文件夹里右键 `一键安装.ps1`，选择"使用 PowerShell 运行"。如果提示禁止运行脚本，先执行下面这一行（只做一次）：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

3. 安装脚本会自动建好独立环境 `.venv`、装好依赖（用国内镜像，比较快），并检查姿态模型文件。

装好后，这个文件夹里会多出一个 `.venv` 文件夹，大约 500MB，属正常现象。

---

## 二、拍视频的要求（很关键）

识别不出来，九成是拍摄问题。按下面的要求拍：

1. 全身入镜，头顶到脚底都要在画面里，不要裁掉脚。
2. 手机固定在椅子上或请人拿稳，距离 2 至 3 米。
3. 侧面拍摄时镜头与髋部同高；正面拍摄时手机放在膝盖高度左右，不要俯拍。
4. 光线均匀，不要背光，不要穿与背景同色的衣服。
5. 一段视频做 3 至 5 次深蹲就够，开头站定 1 秒再开始蹲。
6. 时长控制在 20 秒内，太长会自动截断。

建议一次录两段：一段侧面，一段正面。侧面用来判断深度、前倾和起身时序，正面用来判断膝内扣。

---

## 三、怎么运行

方式一（推荐）：双击运行 `一键运行动作自检.ps1`，按提示粘贴视频路径、选择拍摄角度即可。

方式二：命令行。先进入 `动作自检` 目录，再执行：

```powershell
..\.venv\Scripts\python.exe -X utf8 squat_analyzer.py "..\样例视频\深蹲_侧面.mp4" --view side
```

正面视频把 `--view side` 换成 `--view front`。

---

## 四、输出结果怎么看

运行结束后，`输出结果` 目录里会多出三个文件：

| 文件 | 用途 |
| --- | --- |
| `视频名_骨架.mp4` | 带骨架和实时指标的片段，直接用于演示视频 |
| `视频名_报告.json` | 完整报告，供网站后端和大模型调用 |
| `视频名_结论卡.png` | 一张结论卡片，可以直接当作品简介的功能截图 |

控制台同时会打印结论，例如：最低点膝关节角度、检出的问题、每条问题对应的纠正练习。

---

## 五、判定的四个指标

| 指标 | 判定标准（默认值） | 说明 |
| --- | --- | --- |
| 下蹲深度 | 最低点膝关节角度大于 100 度 | 角度越大说明蹲得越浅 |
| 膝内扣 | 膝盖相对脚踝内移超过肩宽的 10% | 只在正面视角判断 |
| 躯干前倾 | 最低点躯干与竖直方向夹角大于 45 度 | 上身趴得太低 |
| 起身髋先动 | 起身前段髋部完成自身活动范围的比例超过膝部的 1.4 倍 | 俗称早安式起身 |

阈值都写在 `动作自检\pose_rules.py` 的 `DEFAULT_THRESHOLDS` 里，想让判定更严或更松，改数字即可，改完重新运行。

---

## 六、让大模型来写训练建议

数值判定完成后，用这一步交给大模型生成教练口吻的建议：

```powershell
set DEEPSEEK_API_KEY=你的key
..\.venv\Scripts\python.exe -X utf8 llm_explain.py "..\输出结果\深蹲_侧面_报告.json"
```

支持 DeepSeek（`DEEPSEEK_API_KEY`）和通义千问兼容模式（`DASHSCOPE_API_KEY`）。没有 Key 时会自动退回规则生成的建议文案，程序不会报错。

## 七、网站怎么启动

网站已经做好了，在 `网页端` 目录里，包含四个页面：

| 页面 | 功能 | 用到的能力 |
| --- | --- | --- |
| 自检 | 上传训练视频，给出骨架画面、问题判定与纠正练习（支持深蹲、硬拉、卧推、俯卧撑、引体向上） | 姿态算法 + 视觉与语言大模型 |
| 记录 | 说一句话记录训练（含"昨天""上周三"这类日期），自动落到日历；点某天看当天明细与容量；AI 依据历史生成新建议 | 大模型解析 + 长期记忆 + 训练统计 + 规则决策 |
| 吃饭 | 拍一张餐盘或菜单识别菜品（认菜与估份量交给视觉模型，热量蛋白质按菜品库计算），也可手动选菜，并给出蛋白质缺口与具体窗口组合 | 视觉识别 + 知识库检索 + 组合优化 |
| 我的 | 身体数据与目标、主动督导、计划变更历史 | 智能体主动性与可解释闭环 |

启动方式：双击 `一键启动网站.ps1`（第一次会自动装好网页端依赖）。启动后：

1. 电脑上打开 `http://127.0.0.1:8000`（如果 8000 被占用，脚本会自动改用 8123 并提示）；
2. 手机连同一个 WiFi，打开脚本里打印的那个局域网地址，就能在手机上录视频并上传；
3. 需要放到公网时，按 [资料\部署到公网.md](资料\部署到公网.md) 操作。

### 桌面版界面

界面按电脑屏幕设计，左侧是导航栏，右侧是工作区，每个模块都是"主内容 + 右侧信息栏"的两列布局。视觉是**暗色毛玻璃**风格：结构区域用更重的材质、交互区域用更轻的材质，卡片内部用更暗的凹陷材质，底层铺一层环境光斑让玻璃有真实折射；圆角整体偏大，并按要求内建了减弱动态、减弱透明度、提高对比度三组可访问性适配。完整规范见 `资料\设计规范参考.md`。

桌面端可用的快捷操作：

| 操作 | 效果 |
| --- | --- |
| 按 1 至 4 | 在四个模块之间切换 |
| 按 / | 跳到食堂营养并聚焦搜索框 |
| 在输入框按 Enter | 直接解析刚才的记录 |
| 把视频拖到虚线框 | 免点击选文件 |

窗口宽度小于 900 像素时（手机或窄窗口），侧边栏会自动变成顶部横向导航，页面回到单列布局，功能不受影响。

### 训练日历与 AI 建议

「训练记录」页面把"说一句话记训练"和"看训练历史"串成了一条链路：

1. 输入一句话，比如"昨天深蹲 60 公斤 5 组 5 次，最后一组有点吃力"。配了大模型 Key 时由大模型解析，没配时用规则解析，两者都会识别出**动作、重量、组数、次数、强度、是否完成和训练日期**。
2. 日期支持"今天、昨天、前天、大前天、N 天前、上周三、10 月 1 日"这些说法。解析结果会填进表单，你可以改；表单里还实时显示本次容量。
3. 保存后自动跳到那一天的日历格上，格子里的数字就是当天的总容量（超过 1 吨显示成 t）。
4. 点日历上任意有记录的日期，下方会显示当天练了哪些动作、每个动作的重量与组次、每个动作的容量，以及当天的动作数、总组数、总次数、总容量。
5. 点「让 AI 分析我的训练」，系统会把最近 30 天的训练频率、容量变化、肌群分布与各动作的重量变化整理成画像交给大模型，输出下一步安排。没配 Key 时用规则给结论，同样会指出频率、容量趋势和肌群偏科。

**容量怎么算**：容量 = 重量 × 组数 × 每组次数，一次训练的总容量就是把所有动作加起来。自重动作重量记 0，容量不计，但次数照常统计。这是力量训练里通用的训练量指标，比单看重量更能反映一周练了多少。

动作自检如果想单独用接口，`动作自检\api_pose.py` 保留了最小版本：

1. `POST /api/pose/analyze` 上传视频，返回 `job_id`；
2. `GET /api/pose/jobs/{job_id}` 轮询结果。

## 七之二、登录与账号

网站已经加了登录，打开网址会先看到登录页：

- **测试管理员**：`admin / admin123`，登录后能看到并修改「大模型接入」配置。
- **其他同学**：点「注册」自己建账号，数据按账号隔离，互不可见。

密码用加盐哈希（PBKDF2）存在本地数据库，登录状态放在浏览器的 HttpOnly Cookie 里，30 天内免登录。

## 七之三、把大模型接上（比赛演示前必做）

网站默认不调用大模型，教练建议由规则文案生成。要让大模型真正参与，需要填一个平台的 API Key：

1. 用管理员账号登录，进入「我的与计划」，滚动到最下面的「大模型接入」（这个面板只有管理员可见）；
2. 平台选 DeepSeek，把申请到的 Key 粘贴进去，点「保存并测试」；
3. 出现绿底「连接成功」并看到模型回复，就说明接通了。

接通后，动作自检的教练建议、训练记录解析、督导文案都会由大模型生成，页面标签从灰色「规则生成」变成蓝色「大模型生成」。

申请步骤、五个平台对比、常见错误处理都写在 [资料\接入大模型.md](资料\接入大模型.md)。Key 保存在 `配置\ai配置.txt`，不会上传到任何地方。

## 八、常见问题

**提示"未检测到人体"**：按第二节重拍，重点检查是否全身入镜、是否背光、距离是否合适。

**提示"画面可信度不足"**：说明能用的画面太少，通常是人在画面里太小或移动太快，重拍即可。

**报错找不到模型文件**：运行 `工具\下载模型.py`，或者手动下载 `pose_landmarker_lite.task` 放进 `模型` 目录。

**报错无法打开模型文件**：媒体库对新版 MediaPipe 不支持中文路径，程序已自动把模型复制到临时目录再加载，如果仍报错，检查 `模型` 目录里的文件是否完整（约 5.8MB）。

**运行很慢**：默认每秒抽 4 帧、最多 20 秒，一般 3 到 10 秒出结果。觉得慢可以调小 `--max-seconds`。

**结果和实际感觉不一致**：阈值是通用参考值，不是绝对标准。可以在 `pose_rules.py` 里调整，并在作品文档中说明阈值来源。

还需要你们自己验证的部分：

**多录几段不同的视频试。** 目前已经用一段手机拍摄的杠铃深蹲视频（侧拍、竖屏）跑通过全流程，识别、判定与结论卡都正常；不同光线、角度、距离下的效果还需要多试几段。建议先按第二节的要求录一段侧面视频，跑通后再录正面视频。

另外需要你们决定的：网站的四个页面里，如果时间紧张，优先保证"自检"和"记录"两个页面打磨到位，吃饭与督导页面保持可用即可。

如果识别效果不理想，先调整拍摄条件，再考虑调整阈值；不要一上来就改代码。
