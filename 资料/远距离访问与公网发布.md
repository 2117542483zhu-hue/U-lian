# 让远距离的人使用：三种方式

现在的网站跑在你自己的电脑上，只有同一个 WiFi 下能访问。要让外地的人用，有三条路，按"快慢"和"稳不稳"排序。

| 方式 | 耗时 | 适合场景 | 安全性 |
| --- | --- | --- | --- |
| 组网（Tailscale / ZeroTier） | 10 分钟 | 给几个认识的人用 | 最高，不对公网暴露 |
| 内网穿透（cpolar / 樱花 frp） | 10 分钟 | 临时给一个网址试用 | 中，网址泄露就等于公开 |
| 云服务器 + 域名 + HTTPS | 半天 | 正式提交、评委访问 | 高，但要先加登录 |

**重要前提**：现在这个网站没有登录系统，任何拿到网址的人都能看到并修改全部数据。所以给陌生人用的那条路（云服务器）必须先加上登录与数据隔离，否则等于把隐私直接放在网上。

---

## 方式一：组网（推荐先用这个）

思路是把你和对方的电脑放进同一个虚拟局域网，对方通过一个内网地址访问，网站根本不暴露到公网。

1. 你和对方都去 https://tailscale.com/ 注册并安装客户端（免费版够用，个人最多 100 台设备）。
2. 双方用**同一个账号**登录，或者你邀请对方的账号加入你的网络。
3. 在你电脑上运行 `一键启动网站.ps1`，脚本会打印局域网地址，形如 `http://192.168.1.5:8000`。
4. 在 Tailscale 里查看你自己电脑的虚拟 IP（形如 `100.101.102.103`），把它发给对方：`http://100.101.102.103:8000`。
5. 对方打开就能用。如果打不开，检查 Windows 防火墙是否允许 8000 端口入站。

**优点**：不暴露公网，不需要登录系统，别人看不到数据，也不消耗任何公网带宽费用。
**缺点**：对方必须装客户端并加入你的网络；你的电脑必须一直开着。

---

## 方式二：内网穿透（给别人一个网址）

思路是把本机的端口映射到一个公网域名上，对方直接点链接就能访问。

国内可用的工具：

| 工具 | 免费额度 | 说明 |
| --- | --- | --- |
| cpolar | 有免费版 | 网址随机且每次重启会变，带宽有限，国内速度尚可 |
| 樱花 frp / natfrp | 有免费版 | 需要实名，可以申请固定子域名 |
| 花生壳 | 有免费版 | 需要实名，免费版限速较明显 |

以 cpolar 为例：

1. 注册后下载客户端，执行 `cpolar authtoken 你的令牌` 完成绑定。
2. 运行 `cpolar http 8000`（8000 换成你实际用的端口）。
3. 命令会打印一个公网网址，形如 `https://xxxx.cpolar.cn`，把网址发给对方即可。

**注意**：免费版的网址重启就变。如果要撑过评审期，一定要用能固定域名的方案（付费版或樱花 frp 的固定子域名），否则评委打开时链接已经失效。

## 方式三：云服务器 + 域名 + HTTPS（正式提交必须走这条）

比赛明确要求作品能在公网访问，只能在校园网或本机访问的作品会被判无效，所以最终要走这条路。

1. **买服务器**：轻量应用服务器，2 核 2 吉起步，学生机十几元一个月。
2. **先加登录**：这一步不能省。做法见下面"加登录"一节。
3. **上传代码**：把 `健身智能体` 整个文件夹传到服务器（Windows 用远程桌面，Linux 用宝塔或 scp）。
4. **装依赖**：服务器上装 Python 3.11 或 3.12，执行 `python -m venv .venv` 和 `pip install -r requirements.txt`。
5. **配 Nginx 反向代理**，注意三个细节：

```nginx
server {
    listen 80;
    server_name 你的域名;

    client_max_body_size 200m;      # 视频会上传失败，不设这个会报 413
    proxy_read_timeout 300s;        # 姿态分析要跑十几秒，默认 60 秒会断

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
    }
}
```

6. **开 HTTPS**：用 certbot 申请免费证书，或在云服务商控制台申请。没有 HTTPS 浏览器会标"不安全"，手机端上传视频也可能被限制。
7. **做成开机自启**：Linux 用 systemd，Windows 用 NSSM，别用手动开着的命令行窗口。
8. **安全组**：只开 80、443、22，数据库文件和 `配置\ai配置.txt` 不要放在静态目录里。
9. **每天备份**：定时把 `数据\fitness.db` 复制一份，保留最近 7 天。

## 加登录要改什么

不管走哪条路公开出去，都要做这三件事：

1. 用户表加密码字段（存哈希，不要存明文），加一个登录页和会话 Cookie。
2. 把后端里 25 处写死的 `user_id=1` 换成"当前登录用户"，这样每个人的数据才是分开的。
3. 大模型配置面板只对管理员显示，否则任何人都能覆盖你的密钥。

另外建议加：接口限流（防止有人刷爆模型额度）、上传体积限制（防止有人把磁盘塞满）。

比赛附件里写了"若软件设置了用户名和密码，必须在显著位置注明测试用户名和密码"，所以做了登录之后，记得在作品文档和提交说明里给出一个给评委用的测试账号。
